# Disposable Rhai colony runtime fixture

This standalone crate is a feasibility spike, not the game runtime, a production economy, or a certified sandbox. Run `cargo run --manifest-path spikes/colony-runtime/Cargo.toml --example fixture` from the repository root. Rhai is pinned to 1.27.0 with default features off and `std`, `no_module`, `no_time`, `no_float` on; unchecked execution is not enabled. The lockfile pins transitive versions.

Host integration: construct `Snapshot` from trusted engine-independent data, call `Runtime::activate(revision, source, &snapshot)` at a tick boundary, then call `evaluate` on later ticks. Errors leave the previously accepted revision, goals and jobs unchanged. `advance` is a fake step and `goals`/`jobs` are inspectable Rust records; `Diagnostic` contains revision, stage, line where available, and message. No engine objects enter Rhai. The host must own tick ordering and source history. See the example for actual syntax: player-defined functions use Rhai's scripted method dispatch on an opaque `Colony` receiver, with `this` referring to that receiver, and nested `this.supply_workshop(...)` calls execute in the same Rhai evaluation. `keep_stock(key, minimum)` emits a keyed goal and `stock()` queries the copied snapshot. The receiver is constant and has no mutable map of host capabilities or commands. Built-in names and `__host` are reserved.

Fixture rules only: a single stock count represents one inventory/resource, keys are unique per batch, omissions or satisfaction remove jobs immediately, a deficit creates one job per key, and available supply increments its progress on `advance`. A maintained goal stays present when satisfied; a later deficit creates a fresh job ID. A blocked job retains its identity and old revision until removed. This is deliberately not a conservation model, overlap attribution, safe cancellation, completed-job lifecycle, ordered executor-input contract, or an approved economic rule. The stockpile, worker and workshop IDs are fixture data, not an agreed bridge contract. Goal lines report the native call position; nested command call-chain provenance and persistent source storage are not implemented.

Containment experiment: source is limited to 16 KiB, operations to 20,000, call depth to 32, expression depth to 48, functions to 64, variables to 128, strings to 4096 bytes, arrays and maps to 128 entries, goals to 64 with keys at most 64 bytes. Imports are compiled out, `eval` is disabled, no file, network, process, clock, engine objects or script logging callbacks are provided. The restricted fixture language disables `try`, so caught errors cannot silently commit a partial batch; invalid native goal declarations also poison the batch. This restriction is not a security guarantee. One evaluation uses one Rhai top-level invocation, not independent `call_fn` resets. Limits are defensive experiments, not a proof: structural collection limits are **not an aggregate heap guarantee**; source compilation, diagnostic formatting, internal callbacks, coercions, and hostile composed code still need complete bounded-allocation and fuel analysis. `Engine::new()` includes Rhai's standard library, not a proven allowlist. Duplicate same-signature definitions are rejected by the compiler in the exercised case. Do not expose this fixture to untrusted scripts or run it on a production UI thread. A hard allocation quota or process isolation, plus testing and review, remains a production-approval blocker; investigate Lua fallback if required by the agreed criteria.
